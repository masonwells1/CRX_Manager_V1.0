## 2026-09-08 — PR #605: a package-manager subcommand asked to fix is a manifest write

GitHub Codex P1 (comment 3961112096, on `review-proof-guard.mjs`): `yarn constraints --fix`
persists every changed workspace `package.json` (Yarn 4 documents `--fix` as automatically fixing
unambiguous issues), yet `constraints` sat in the read/run allowlist and the only FIX check was
written for `audit`, so the globally allowed Bash call rewrote protected manifests past the
native-editor prompt. Probe-confirmed: the previous hook answers nothing to the command.

Fix by class: a `fix` word or `--fix*` flag after any subcommand that is not a script runner
(`run`, `test`, `start`, …) is a manifest write, so `audit fix`, `constraints --fix` and `pkg fix`
are one rule; `npm run lint -- --fix` and `npm test -- --fix` stay allowed because those flags
belong to the project's script. `npm config fix` over-blocks; accepted on the hook's standing rule
that a false refusal is the cheaper failure.

Proof: seven deny cases (bare, `--json`, through Corepack, versioned descriptor, `cd … &&`,
`npm pkg fix`, `npm audit --fix`) and six allow cases in `review-proof-guard.test.mjs`; the previous
hook, swapped in place, fails at `yarn constraints --fix`.
