## 2026-09-17 - PowerShell's reading now treats every backslash as ordinary, not just one before a space

- **What changed:** `splitCommandSegments` in `.claude/hooks/codex-push-lib.mjs` doubles EVERY backslash for its third (PowerShell) reading. It used to double only a backslash that preceded whitespace.
- **Why:** a backslash is an ordinary character in PowerShell everywhere — before a space and before a quote alike — while the POSIX word splitter treats it as an escape. The 2026-09-14 fix covered only the space form, so `gh api --template \"x" -X DELETE repos/o/r/git/refs/heads/feature` still hid its DELETE: POSIX swallowed the quote and read the rest of the line as one quoted word. Found by the local gpt-5.6-sol review of PR #630 on 2026-09-14 (round 4). This one was a real regression — `origin/main` denies that command and the candidate allowed it.
- **Proof:** the real Codex production guard ran as a hook subprocess on that exact command against both the candidate and `origin/main`'s guard files; the candidate now denies it with the same `gh api` message main uses. Reverting the one-line change makes the new shared-library assertion (`a PowerShell \"foo" --admin reading exposes --admin`) and the new Codex end-to-end case (backslash-quote `-X DELETE`) both fail. New cases cover the hidden `--admin`, a hidden `--repo`, and the hidden `-X DELETE`; the existing control still proves a command with no backslash gains no extra reading.
