# Farm Field Boundary Data Sources — Research Report (M12, 2026-07-11)

Research-only deliverable of the ChemMan-parity loop (unit M12). No code, no DB changes.

## 1. Can you legally get real USDA CLU data?

**Short answer: no, not as a live, scalable API — and this hasn't changed for 2026.**

Section 1619 of the 2008 Farm Bill made CLU (Common Land Unit — the FSA's official field-boundary dataset) private data and barred USDA from releasing any **newer** CLU information without the landowner's consent ([FSA CLU Information Sheet](https://www.fsa.usda.gov/Internet/FSA_File/clu__infosheet_2013.pdf), [GeoDataPolicy summary](https://geodatapolicy.wordpress.com/tag/common-land-unit/)). The only "legitimate" access paths that still exist:

- **The landowner/operator themselves** can walk into their local FSA office and request the shapefile for their own farm ([FSA GIS Fact Sheet](https://www.fsa.usda.gov/Internet/FSA_File/11_gis.pdf)). This is a manual, per-farm, in-person/paperwork process — not an API a company can build against.
- **USDA "cooperators"** (other government agencies/researchers) can get authorized disclosure under Sec. 1619, but this is not a route open to a private ag-retail software vendor.

The critical fact nobody advertises clearly: **USDA stopped distributing updated CLU data entirely.** The last national release was the **2008 snapshot**, before the restriction fully took hold. Everything in the ag-tech industry that is labeled "FSA CLU boundaries" today — in Surety, LandID, Acres.com, etc. — is that same **frozen 2008-vintage dataset**, now 18 years stale, repeatedly relicensed/resold ([id.land FSA CLU Overlay docs](https://support.id.land/fsa-clu-overlay), [2008fsaclu.com reseller](https://2008fsaclu.com/)). It explicitly gets served with "use for reference only" warnings for exactly that reason — real fields have split, merged, been tiled, or changed since 2008.

## 2. What ChemMan most likely uses

Given AgriData Inc.'s **Surety / Surety Pro** product markets itself specifically as an embeddable ag-mapping layer for third-party farm software (Web Services API + WMS + "Integration Services" for vendors with limited mapping capability of their own — [agridatainc.com Web Services](https://www.agridatainc.com/Home/Services/Web%20Services)), and its flagship feature is literally "click existing FSA CLU boundary to adopt it, or draw your own" ([Surety product page](https://www.agridatainc.com/Home/Products/Surety)), this is almost certainly the vendor behind ChemMan's "click-to-adopt" experience — or a close AgriData competitor doing the same thing (LandID/id.land is the other candidate). ChemMan's own marketing confirms the same UX pattern: start from predetermined FSA borders or draw your own polygon ([chem-man.com/mapping](https://www.chem-man.com/mapping)). Pricing for Surety's Web Services isn't published — it requires an active/trial Surety account and a direct sales conversation ([agridatainc.com/Account/Price](https://www.agridatainc.com/Account/Price)).

## 4. Plain-English recommendation

**Recommended path: build the "click to adopt" feature on USDA Crop Sequence Boundaries (CSB), not on any FSA/CLU-branded product.**

Why: the "true" USDA field boundary data (CLU) has been legally locked up since 2008, and every commercial vendor that advertises "FSA CLU boundaries" — including whatever ChemMan is almost certainly using (AgriData's Surety) — is actually reselling that same 18-year-old frozen snapshot, with an explicit "reference only, may be inaccurate" disclaimer. Paying a vendor for that doesn't get CRX Manager anything more accurate than what's free.

USDA's **Crop Sequence Boundaries** dataset, by contrast, is free, public domain, has no licensing office to negotiate with, and — unlike a tax-parcel dataset (Regrid/ReportAll/ATTOM) — its polygons are actual **agronomic field shapes** derived from real satellite-observed crop patterns, which is what you want for spray/application acreage, not ownership lot lines. CSB releases are multi-year synthetic windows rather than annual snapshots, so check the [NASS CSB page](https://www.nass.usda.gov/Research_and_Science/Crop-Sequence-Boundaries/) for the latest window before building; 2018–2025 may now be current. Since CRX Manager already has a manual field-drawing/editing tool, CSB slots in perfectly as the "click a field, adopt the shape, then nudge it if it's off" starting point — the same UX Mason likes from ChemMan, built on a legally clean, free foundation instead of a licensed reseller of stale government data.

One clear next step: confirm the latest CSB window on the NASS page, pull its shapefile for Illinois/Indiana, load it into the map, and try the "click a parcel → adopt boundary → edit" flow against a few known Crawford County fields to see how well it lines up before committing engineering time. If CSB boundaries prove too rough in practice, the fallback upgrade path is a ReportAll USA API trial (cheapest, best-documented parcel API) as a supplemental "ownership outline" layer — not a CLU purchase.

**Skip:** licensing AgriData/Surety, LandID, or a 2008 CLU reseller. They cost money for boundary data that is provably the same age or older than the free CSB alternative, and none offer a materially better legal footing than "use for reference only."
