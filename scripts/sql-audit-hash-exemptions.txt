# SQL AUDIT — HASH-PINNED VIOLATION EXEMPTIONS (Codex Medium, round 24)
#
# Read by scripts/validate-sql-migrations.sh.
#
# WHY THIS FILE EXISTS
#
# CI runs the audit with --max-violations=61, an AGGREGATE allowance for the
# legacy findings in migrations that were already applied live and so may not
# be edited. An aggregate is a pool. When a new check starts firing on more of
# that history, raising the number is the obvious move and the wrong one: the
# corpus gains N free slots, and when one old finding is later fixed its slot
# does not close — a genuinely new violation can take it while CI stays green.
#
# A row here pins one acknowledged finding to one file's exact bytes instead:
#
#   - the exemption applies only while the file still hashes to the recorded
#     value, so any edit to it voids the exemption;
#   - it applies only to that file, so no other migration can consume it;
#   - it applies only up to <count>, so an additional violation in the same
#     file still counts against the baseline;
#   - and when the file stops violating, the audit prints a STALE EXEMPTIONS
#     block naming the row, so it gets removed instead of lingering as headroom.
#
# FORMAT
#
#   <sha256>  <basename>  <count>   # <why this finding is acknowledged>
#
# The hash is sha256 over the file's bytes with every CR removed, so a CRLF
# checkout on Windows and an LF checkout on Linux agree. Regenerate one with:
#
#   node -e "const{createHash}=require('crypto'),fs=require('fs');\
#   process.stdout.write(createHash('sha256').update(Buffer.from(\
#   fs.readFileSync(process.argv[1],'latin1').replace(/\r/g,''),'latin1')).digest('hex'))" \
#   supabase/migrations/<file>.sql
#
# Adding a row is a reviewed decision, not routine upkeep. The right first move
# for a new violation is to FIX it. A row here asserts two things, both of which
# someone checked by reading the flagged lines: the finding is benign, and the
# file is not this change's to repair — it is already applied live (AGENTS.md
# forbids editing those), or it belongs to work that has already merged and the
# correct fix is a validator change tracked separately.
#
# ---------------------------------------------------------------------------
